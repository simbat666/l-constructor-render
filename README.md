# L Constructor — локальный MVP

Поле 8 × 5 с независимыми блоками электродвигателей, опросником из ОЛ,
предварительным расчётом I/O и скачиваемой черновой компоновкой DXF.

## Запуск

Требуются Node.js ≥ 22.13 и Python ≥ 3.11 для установки всего указанного набора зависимостей.
AutoCAD, Excel и конвертер DWG для работы сервера не нужны.

```sh
npm ci
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-cad.txt -r requirements-rules.txt
npm run cad
```

В другом терминале, из корня проекта:

```sh
npm run dev -- --port 3003
```

Открыть http://localhost:3003. CAD слушает только `127.0.0.1:3001`.
Браузер обращается к `/api/cad`, веб-сервер передаёт запрос локальному Python-процессу.
Для проверки production-сборки: `npm run build`, затем `npm run start -- --port 3003`.
Не запускать dev и start одновременно на одном порту.

## Как скачать схемы

1. Добавить нужное количество блоков на поле и заполнить опросник каждого.
2. В опроснике нажать «Проверить схемы» → «Собрать DXF» для отдельных схем одного блока.
3. В правой панели нажать «Собрать схемы шкафа». Появятся отдельные ссылки:
   «Принципиальная электрическая схема · DXF», «Схема внешних соединений · DXF», а также комплект ZIP.
   Оба документа собираются по всем блокам поля и получают свои рамки и страницы.
4. «Скачать расчёт JSON» сохраняет ответы, выбранные строки, I/O, диагностику и экземпляры схем.

Незаполненный блок не исчезает из общей выгрузки: кнопка всего шкафа блокируется с диагностикой.
Повторяющиеся моторы и датчики остаются разными экземплярами. Файлы находятся в
`output/generated`, имеют уникальный идентификатор. Перезагрузка вкладки пока стирает ответы;
JSON — экспорт данных, его обратная загрузка пока не реализована.

**DXF пока черновой:** внутри шаблонов остаются исходные надписи и номиналы.
Это не автоматически выпущенная электрическая КД. Логические адреса I/O не являются клеммами
конкретного контроллера. Открытие в AutoCAD проверяется отдельно от аудита ezdxf.

## Обновление базы

Оригиналы не перезаписывать. Активировать `.venv`, импортировать сначала во временный файл:

```sh
npm run rules:sync -- --source "/полный/путь/Новая ОЛ.xlsx" --target "/tmp/l-motor-candidate.json" --revision "В2 — дата ревизии"
```

Сравнить источник, все таблицы и диагностические сообщения; затем осознанно обновить рабочий
`data/motor-v2.json`, выполнить тесты и пересобрать приложение. XLSX не перечитывается при каждом клике.
