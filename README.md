# L Constructor — локальный MVP

Поле 8 × 5 с независимыми блоками электродвигателей, опросником из ОЛ,
распределением I/O по выводам ZENTEC M245 и тестовым модулям `M245 no display`
и скачиваемой черновой компоновкой DXF.

## Запуск

Требуются Node.js ≥ 22.13 и Python ≥ 3.11 для установки всего указанного набора зависимостей.
AutoCAD, Excel и конвертер DWG для работы сервера не нужны.

```sh
npm ci
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-cad.txt -r requirements-rules.txt
npm run cad
```

В другом терминале, из корня проекта:

```sh
npm run dev -- --port 3003
```

Открыть http://localhost:3003. CAD слушает только `127.0.0.1:3001`.
Браузер обращается к `/api/cad`, веб-сервер передаёт запрос локальному Python-процессу.
Python выполняет весь инженерный расчёт, выбирает видимые вопросы и собирает DXF.
Интерфейс отправляет ответы через 250 мс после ввода; при недоступности API показывает ошибку
и блокирует экспорт устаревшего результата. Полная база правил остаётся на сервере.
Для проверки production-сборки: `npm run build`, затем `npm run start -- --port 3003`.
Не запускать dev и start одновременно на одном порту.

## Доступ для двух пользователей

В production доступ к расчёту и файлам CAD требует сессию. Логины и хеши паролей
хранятся только в root-доступном `/etc/l-constructor/auth.env`, а не в Git:
`L_AUTH_SESSION_SECRET`, `L_AUTH_USER_1`, `L_AUTH_PASSWORD_HASH_1`,
`L_AUTH_USER_2`, `L_AUTH_PASSWORD_HASH_2`. Хеш имеет вид `scrypt:<salt>:<hash>`.
Без этого файла production API не откроется. Для реального использования нужен HTTPS:
на обычном HTTP пароль передаётся без транспортного шифрования.

## Как скачать схемы

1. Добавить нужное количество блоков на поле и заполнить опросник каждого.
2. В опроснике нажать «Проверить схемы» → «Собрать DXF» для отдельных схем одного блока.
3. В правой панели нажать «Собрать схемы шкафа». Появятся отдельные ссылки:
   «Принципиальная электрическая схема · DXF», «Схема внешних соединений · DXF», а также комплект ZIP.
   Оба документа собираются по всем блокам поля и получают свои рамки и страницы.
4. «Скачать расчёт JSON» сохраняет ответы, выбранные строки, I/O, диагностику и экземпляры схем.

Незаполненный блок не исчезает из общей выгрузки: кнопка всего шкафа блокируется с диагностикой.
Повторяющиеся моторы и датчики остаются разными экземплярами. Файлы находятся в
`output/generated`, имеют уникальный идентификатор. Проекты и рабочие области сохраняются
локально в браузере; JSON — отдельный экспорт расчёта, его обратная загрузка не реализована.

**DXF пока черновой:** у `im1-011`–`im1-014` по проверенным полям подставляются
выводы базового PLC, отдельные обозначения GND и зажимы XT1. В остальных шаблонах
клеммы и выводы PLC остаются как в источнике; там меняются только подтверждённые
обозначения QF/KM/KL. Если сигнал назначен модулю, комплект получает отдельный
подписанный лист модуля без его геометрии и клемм. Объединение GND/COM и связи
между схемами ещё не параметризованы. Это не выпущенная электрическая КД.

## Обновление базы

Оригиналы не перезаписывать. Активировать `.venv`, импортировать сначала во временный файл:

```sh
npm run rules:sync -- --source "/полный/путь/Новая ОЛ.xlsx" --target "/tmp/l-motor-candidate.json" --revision "В2 — дата ревизии"
```

Сравнить источник, все таблицы и диагностические сообщения; затем обновить рабочий
`data/motor-v2.json`. Для состава и ключей M245 используется `scripts/extract_plc_rules.py`,
который создаёт `data/plc-catalog.json` из двух XLSX в `data/rules-source`. После обновления
любого источника выполнить тесты и перезапустить Python-сервис. Отпечаток расчёта учитывает
все три книги. XLSX не перечитываются при каждом клике.

## Где находится логика

- `scripts/questionnaire.py` — граф и проверка ответов ОЛ.
- `scripts/cabinet_engine.py` — подбор, спецификация и объяснение результата.
- `scripts/io_allocator.py` — подбор минимального числа модулей и распределение по
  отдельным выводам M245/M1…M5 без повторного занятия физического ресурса.
- `scripts/local_cad_api.py` — API расчёта и экспорта; экспорт всегда пересчитывается на сервере.
- `app/`, `components/`, `lib/engineering-client.ts` — интерфейс и связь с Python.
- `tests/fixtures/engine-cases.json` — неизменяемые входы и ожидаемые результаты Python-движка.
